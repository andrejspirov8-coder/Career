# Career Workspace — MCP (Model Context Protocol) Architecture\n\n**Date:** 20 May 2026 | **Status:** Design + Partial Implementation\n\n---\n\n## Current State: MCP Foundation Exists, But Underutilized\n\nYou already have a **proto-MCP harness** in `mcp_harvest_score.py` that:\n\n1. Reads LinkedIn profile stubs from JSONL\n2. Scores them against your CV variants\n3. Appends results to `recruiter_action_plan.jsonl`\n4. Logs row-by-row to `recruiters.csv`\n\nBut the MCP is **input-only**: other agents feed you profiles, you score them, outputs go to files. There's no **bi-directional tool exposure** — other agents can't ask your scorer to evaluate a specific profile in real-time.\n\n---\n\n## Vision: Agentic Recruiter Scoring as a Composable Tool\n\nInstead of:\n```bash\npython tools/mcp_harvest_score.py pipeline/stubs.jsonl → recruiter_action_plan.jsonl\n```\n\nExpose:\n```\nMCP Tool: score_recruiter_profile()\n  Input: {headline, company, about, name, location, variant_slug}\n  Output: {\n    variant_slug_best: str,\n    primary_score: float,\n    confidence: str,\n    tier: str,\n    note_preview: str,\n    reason_skipped: str (if applicable)\n  }\n```\n\nSo other agents (Desktop Commander, Cursor, external Claude instances) can:\n1. **Discover** candidate profiles (web search, LinkedIn API stub, your inbox)\n2. **Score them** by calling your MCP tool\n3. **Reason about them** (e.g., \"This recruiter is Tier 1 because…\")\n4. **Take actions** (auto-save to backlog, notify you, queue for dispatch)\n\n---\n\n## MCP Server Implementation (Minimal MVP)\n\n### Architecture\n\n```\nDesktop Commander / External Agent\n        ↓\n   MCP Client\n   (sends requests)\n        ↓\nMCP Server (localhost:8000, stdio, or WebSocket)\n        ↓\nRecruiter Scoring Engine\n├─ recruiter_match.match_recruiter_profile()\n├─ recruiter_match.assign_best_tier()\n├─ recruiter_match.prepare_outreach_note_bundle()\n└─ recruiter_match.should_send_recruiter_connection()\n        ↓\nResults cached in SQLite (recruiters.csv)\nor returned directly to client\n```\n\n### Proposed File Structure\n\n```\njob-search/\n├── mcp/\n│   ├── __init__.py\n│   ├── server.py          ← MCP server (stdin/stdout or async HTTP)\n│   ├── tools.py           ← Tool implementations\n│   ├── resources.py       ← Optional: expose CV variants, config as resources\n│   └── handlers.py        ← Request routing\n├── tools/\n│   ├── mcp_harvest_score.py (refactor to call mcp/tools.py)\n│   └── ...\n└── config/\n    ├── mcp_config.yaml
