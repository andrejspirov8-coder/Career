### REL-001 — No migration strategy for 3 of 5 SQLite databases (MEDIUM)

- **Status:** New (previous review overstated — partially present, not absent)
- **Severity:** Medium
- **Risk score:** 40 (impact: 4, likelihood: 3, exposure: 2, urgency: 1)
- **Effort:** M
- **Confidence:** High
- **Evidence:** EV-006, EV-007, EV-008
- **Component:** All database modules
- **Details:**
  - `core/sqlite.py` — provides shared `migrate_schema()` helper with versioned `schema_meta`
  - `recruiters/repository.py` — **HAS** schema versioning (`SCHEMA_VERSION = 2`, uses `schema_meta`)
  - `opportunities/repository_db.py` — **HAS** schema versioning (`SCHEMA_VERSION = 3`, uses `migrate_schema()`)

  - `automation/control.py` — **NO** SQLite migration code
  - `workspace/control.py` — **NO** SQLite migration code
- **Why it matters:** Schema drift between environments will cause silent failures or data loss for 3/5 databases.
- **Recommended fix:** Apply `core/sqlite.py`'s `migrate_schema()` to notifications, automation, and workspace databases.
- **Verification:** Integration test that creates each DB, checks schema version, and verifies version increment on migration.
